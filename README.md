# Onlinepolis — учёт страховых полисов

Веб-приложение страхового брокера: клиенты и страховщики, полисы и графики
платежей, комиссии, очередные взносы, пролонгация, исходящие письма,
Excel-отчёты и аналитика. Из акцептованного свода InsFlow можно начать
оформление полиса или связать свод с существующим полисом.

**[Оглавление документации](docs/README.md)** ·
[Руководство пользователя](docs/USER_GUIDE.md) ·

Описание сверено с исходным кодом 2026-11-11. Состояние production и внешних
сервисов не следует из наличия функции в коде; эксплуатационная история
и принятые решения находятся в бэклоге и архиве.

## Стек

Python 3.12, Django 5.2.19 LTS, PostgreSQL 15 в production / SQLite по умолчанию
в разработке, Celery + Redis 7, Bootstrap 5, Gunicorn и Nginx.
Версии зависимостей закреплены в [requirements.txt](requirements.txt) и
[requirements.prod.txt](requirements.prod.txt).
Язык интерфейса — русский, часовой пояс — `Europe/Moscow`.

## Локальный запуск

Нужен Python 3.12. Команды выполняются из корня проекта.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если локального `.env` ещё нет, скопируйте `.env.example` в `.env`.
Для SQLite оставьте `DB_NAME` пустым. Существующий `.env` не перезаписывайте.

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Для **новой пустой базы** после миграций можно загрузить начальные справочники:

```bash
python manage.py loaddata fixtures/initial_data.json
```

Фикстура содержит фиксированные ID: на существующей базе она может перезаписать
справочники. Пользователь создаётся отдельно; готовой учётной записи с общим
паролем приложение не предоставляет.

Адрес разработки: <http://127.0.0.1:8000/>.
Для очереди писем и фоновых уведомлений нужны Redis и Celery; запуск описан
в [руководстве разработчика](docs/DEVELOPMENT.md).

## Production

Канонический адрес — <https://polis.insflow.ru/>. Workflow запускается при
push в `main` и вручную через GitHub Actions. CI проверяет код, собирает один
образ `linux/amd64`, проверяет его с Redis/PostgreSQL и передаёт серверу через
ограниченный SSH-контроллер. Сервер использует готовый образ.

Прочитайте [руководство по деплою](docs/DEPLOYMENT.md) перед
изменениями инфраструктуры или восстановлением. Обычный релиз не обновляет
серверные скрипты, Compose, Nginx и `.env.prod`. Автоматическое восстановление
возвращает образы приложения; миграции БД, media и static назад не возвращаются.

## Навигация по коду

- `apps/` — приложения и бизнес-логика;
- `config/` — настройки Django, маршруты и Celery;
- `templates/`, `static/` — интерфейс;
- `scripts/` — скрипты хоста и контроллер деплоя;
- `nginx/` — конфигурация reverse proxy;
- `docs/` — руководства, бэклог и архив.

Карта приложений, модель данных и правила расчётов:
[architecture.md](docs/architecture.md).
