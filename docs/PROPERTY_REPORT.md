# Имущественный отчёт для лизинговой компании

`/reports/property-report/` доступен авторизованным сотрудникам. Параметры:
`as_of`, повторяемый `branch`, `structure_scope=all|broker|direct`.

- **Скачать PDF**: `format=pdf`, готовый документ как вложение.
- **Печатать отчёт**: `format=pdf&disposition=inline`, тот же формат документа
  открывается в новой вкладке PDF-просмотра с действием печати.
- **Excel**: `format=xlsx`, те же дата, состав и методика.

## Основная часть и приложения

Основная часть занимает восемь A4-страниц: резюме, состав имущества,
страховщики, филиалы, динамика, окончания/кандидаты на продление,
крупные позиции/лизингополучатели, методика и сверка.
Для печати только основной части выбирают страницы 1–8.

Полные приложения продолжаются автоматически: страховщики и все менеджеры,
две матрицы, характеристики имущества, 20 крупнейших записей с полными
описаниями, крупные окончания, ответственность. Широкие матрицы печатаются
альбомными листами, по шесть столбцов; итоги строк означают всю строку,
включая столбцы других частей. Заголовки таблиц повторяются. Очень длинное
описание может продолжаться на следующем листе, без сокращения текста.
Количество страниц приложений зависит от выбранного среза.

## Методика 2.0

СС: общий helper текущего страхового года, без замены неизвестного значения
максимумом. Состав: полисы в силе с активным на дату ДФА, без ОСАГО.

В подробном отчёте именованный вид справочника **«Ответственность»**
(без учёта регистра и внешних пробелов) вынесен отдельно: лимиты не включаются
в СС имущества, количество и распределения имущественного портфеля.
Сводка показывает СС имущества + сумму лимитов отдельно — это уже не общий
срез Дашборда: Дашборд и краткий срез применяют то же правило, и имущественные
итоги на одну дату при одинаковых фильтрах совпадают с отчётом и слайдами
презентации. Новые виды ответственности с другими названиями
потребуют явного расширения классификации, а не распознавания описания.

Количество — страховые записи, а не уникальные физические объекты.
Средняя СС исключает записи с неизвестной СС. Филиал означает обслуживание,
а не фактическое местонахождение имущества.

Окончания — договорные даты окончания действующих записей. Кандидаты на
продление дополнительно требуют продлеваемого вида, продолжающегося после
окончания ДФА и отсутствия известного раннего расторжения. Это не очередь
обязательных действий: новый связанный полис может быть уже оформлен.
Горизонты 30/60/90 накопительные. Календарь начинается с даты среза и
показывает текущую СС, не прогноз стоимости следующего года.

История восстановлена из текущей базы. Изменение СС не тождественно росту
имущества. Марки и пометки состояния распознаются по свободному описанию.
В документ не входят КВ, премия, тариф, доходы и внутренние платёжные задачи.

## Реализация и проверки

`property_document.build_property_document` — единые данные HTML/PDF/Excel;
`property_pdf.build_property_pdf` — генератор без запросов к БД и сети.
Два прохода дают точные номера страниц; PDF содержит закладки разделов.
Inter встраивается из `static/fonts/inter`; логотипы читаются только из
трёх каталогов справочников внутри `MEDIA_ROOT`. Некорректные/отсутствующие
изображения пропускаются с сохранением названия. Текст XML-экранируется.

Обычный PostgreSQL-запрос собирает данные в read-only repeatable-read
транзакции. Все ответы запрещают кэширование в браузере; PDF выдаётся с
`application/pdf`, `nosniff`, явным attachment/inline. Файл формируется
заново при запросе, с датой формирования и версией методики. Сохранённый
пользователем PDF фиксирует результат. Архива ранее выданных файлов в
приложении пока нет.

Тесты: `pytest tests/test_property_pdf.py tests/test_property_report.py
apps/core/tests/test_dashboard_v3.py`, затем полный `pytest`.
Проверяются роли, отсутствие КВ в SQL/тексте, фильтры, отделение лимитов,
восемь основных страниц, пустые срезы, много страховщиков, очень длинные
описания, приложения и безопасная загрузка изображений.
