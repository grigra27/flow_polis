# Документация Onlinepolis

Руководства сверены с исходным кодом **2026-11-11**. Они описывают поведение
приложения и процедуры, предусмотренные репозиторием. База полной сверки — версия кода
`30e4a9e`; последующие исправления сопровождаются целевыми проверками. Это не новая проверка
production: доступность SMTP, установленный cron, сертификаты и применённые
на сервере настройки проверяются отдельно.

## История и задачи

[Архив](archive/README.md) содержит прежние планы и эксплуатационные аудиты.
Дата и статус в архивном тексте относятся к моменту его написания.
Старые материалы по ранним версиям, календарю и отменённому публичному API
удалены из рабочей документации; их исходное содержимое сохраняется в Git.

Все открытые и отложенные задачи, принятые риски и решения владельца ведутся
**только в [BACKLOG.md](BACKLOG.md)**. Подробная спецификация может лежать отдельно,
но её старые галочки не заменяют актуальный статус задачи.

Локальные корневые `CLAUDE.md` и `PLAN.md` исключены из Git. Первый помогает
агенту ориентироваться в проекте; второй содержит историю старого плана.
Они не заменяют общую документацию и единый бэклог.

## Как обновлять документацию

1. Сверять изменение с указанным исходным файлом, а для production-фактов —
   с результатом отдельной проверки и её датой.
2. Менять руководство в том же изменении, что и описываемое поведение.
3. Давать ссылку на основное руководство вместо копии тех же инструкций.
4. Не переносить пароли, токены, приватные ключи и реальные `.env` в документы.
5. После объединения файлов обновлять ссылки и якоря. Историю решений сохранять
   в Git или в архиве, не выдавая её за действующую инструкцию.
