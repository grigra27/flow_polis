## 1. Исходная ситуация

### 1.1. Что есть сейчас

9 страниц (`/analytics/…`): сводка, филиалы, филиалы v2, страховщики, клиенты,
финансы, финансовая история, временные ряды, ОСАГО. Около 10 тыс. строк Python
(`services.py` — 3,9 тыс., `views.py` — 3,2 тыс., `exporters.py` — 2,3 тыс.)
и 8 тыс. строк шаблонов.

Проблемы:

- **Разные определения денег.** «Финансы» и «Временные ряды» уже считают
  «заработано» по дате акта с СК (`money.py`, коммит 41f751f), сводка — по
  старой модели «оплачено в закрытых месяцах + план», «Финансовая история» —
  по оплатам в месяце платежа. Одна и та же величина на разных страницах
  разная.
- **Дубли.** Две страницы филиалов; три страницы про деньги во времени;
  в каждом view свой разбор фильтра, свой POST-обработчик, свой экспорт.
- **Бессмысленные показатели.** «Рыночная доля» — на самом деле доля в
  собственном портфеле; сумма страховых сумм через «мост» периодов;
  «средний рост в месяц» и тренды на истории длиной в год; индекс здоровья.
- **Не используется.** За 3 дня логов nginx — 5 открытий раздела (все —
  `/analytics/financial/`).

### 1.3. Решения владельца (2026-10-16)

1. Разделом пользуется **только владелец** — доступ остаётся
   `SuperuserRequiredMixin`, без ролей и фильтра «мой филиал».
2. **Плана продаж нет и не будет** — блоков «факт против плана» нет.
3. **Очередные взносы для аналитики не используются.** Оплаченный взнос
   автоматически уходит со страницы, статусы задач не ведутся (ход работы
   пишется в комментарий), поэтому скорость выставления счетов не
   измерить.
4. **Закрытие ДФА** — как правило, досрочный выкуп (клиент забирает
   технику), но бывает и плановое закрытие в срок. Делим приближённо по
   датам (см. §3).
5. **`renewal_to_old_dfa`** — новый полис к существующему договору лизинга.
6. **Новых полей в модели не добавляем** («предыдущий полис», «причина
   закрытия»). Где нужно — используем приближённые расчёты, описанные в §3.
7. **Полисы «без участия брокера»** (`broker_participation = False`)
   исключаются из всех показателей и показываются отдельной строкой
   «без участия брокера».
8. **Досрочный выкуп** — ДФА закрыт раньше окончания полиса более чем на
   **30 дней**.
9. **Продление — только в рамках того же ДФА.** Новый полис на тот же
   объект под другим номером ДФА фактически невозможен, поэтому VIN для
   сопоставления не используется. Отдельного «продления» как процесса
   обычно нет — блок удержания показывает, сколько полисов с активным ДФА
   получили новый полис по этому ДФА.
10. Окно сопоставления ±45 дней и пороги сигналов (§4 A) — утверждены
    как предложены.

## 2. Принципы

1. **Один словарь денег** (§3) в одном модуле (`apps/analytics/money.py`).
   Ни одна вкладка не считает деньги своим способом.
2. **Одна панель фильтров** на весь раздел: период, филиал, СК, вид
   страхования, менеджер лизинга, «с ОСАГО / без ОСАГО». Фильтры в
   GET-параметрах — ссылку можно сохранить в закладки.
3. **Каждая цифра — ссылка на список**, из которого она сложилась
   (платежи или полисы), с выгрузкой в Excel.
4. **Каждый блок отвечает на вопрос.** Если вопроса нет — блока нет.
5. **Честные сравнения:** «год к году» — только за одинаковые периоды
   (01.01 – сегодня против 01.01 – та же дата прошлого года) и только
   начиная с 2025.
6. **ОСАГО** по умолчанию исключено (как сейчас), переключатель включает.
7. Оперативные блоки главной страницы (ближайшие платежи, «Дашборд 2.0»)
   в аналитике не повторяются.

## 3. Словарь: как считается каждая величина

### 3.1. Деньги (платежи `PaymentSchedule`)

| Величина | Определение | Дата для периода |
|---|---|---|
| **Заработано** | `insurer_date` заполнена | `insurer_date` |
| **Ждёт акта** | `paid_date` заполнена, `insurer_date` пуста | возраст = сегодня − `paid_date` |
| **Ожидается** | не оплачен и не отменён, `due_date ≥ сегодня` | `due_date` |
| **Просрочено** | не оплачен и не отменён, `due_date < сегодня` | `due_date` |
| **Потеряно** | не оплачен и отменён: полис неактивен (`policy_active=False`) или платёж после даты закрытия ДФА (`dfa_deactivated_payments_q`) | дата события (см. ниже) |
| **Обеспечено на будущие годы** | ожидается, `due_date` в будущих календарных годах | `due_date` |

Дата события потери: `termination_date` для расторжения, иначе
`dfa_deactivation_date`. Если ДФА закрыт без даты, все неоплаченные платежи
полиса считаются потерянными (в `money.cancelled_q`; раньше они ошибочно
оставались «ожидается»), причина — «не определено», в период они не попадают
и показываются отдельной строкой со ссылкой.

**Причина потери** (приближённо, без новых полей):

| Причина | Правило |
|---|---|
| Расторжение полиса | `termination_date` заполнена |
| Досрочный выкуп | ДФА закрыт, `dfa_deactivation_date < end_date − 30 дн.` |
| Плановое закрытие ДФА | ДФА закрыт, дата закрытия в пределах 30 дн. до окончания полиса или позже |
| Не определено | ДФА закрыт без даты; полис неактивен без даты расторжения |

Порог 30 дней — константа в коде, её можно поменять.

### 3.2. Портфель (полисы `Policy`)

| Величина | Определение |
|---|---|
| **В силе на дату D** | существующий `in_force_q(D)` |
| **Новый бизнес** | полис с `start_date` в периоде; премия и КВ — по платежам `year_number = 1` |
| **Новый полис к старому ДФА** | новый бизнес с `renewal_to_old_dfa = True` (показывается отдельной строкой) |
| **Требовал продления** | `end_date` в периоде, не расторгнут, ДФА активен на `end_date` (`dfa_active` или `dfa_deactivation_date > end_date`) |
| **Продлён** (приближённо) | существует другой полис (не ОСАГО) с тем же `dfa_number`, `start_date` в окне `end_date ± 45 дн.`. VIN не используется. Один ДФА может включать несколько объектов (на проде 100 ДФА с несколькими полисами, до 11), поэтому расчёт приближённый |
| **Ушёл к другой СК** | продлён, но у нового полиса другой страховщик |
| **Тариф года** | премия года / страховая сумма первого взноса года (как `get_rates_by_year`) |

Окно ±45 дней и правило сопоставления — константы в одном месте, покрыты
тестами.

## 4. Состав раздела

Одна страница `/analytics/` с вкладками; у каждой вкладки свой адрес
(`/analytics/money/`, `/analytics/sales/` и т.д.), фильтры общие.

### A. Сводка — `/analytics/`

Вопрос: *«Как идут дела и на что обратить внимание прямо сейчас?»*

- **Мост КВ за год:** заработано → ждёт акта → ожидается до 31.12 = итог
  года. Рядом отдельно: просрочено, потеряно с начала года.
- **Заработано с начала года vs тот же период прошлого года** (КВ, %).
- **Новый бизнес:** текущий месяц и квартал — полисов, КВ первого года;
  сравнение с тем же периодом прошлого года.
- **Обеспечено на будущие годы:** КВ по графику на следующий год и далее.
- **Сигналы** (3–7 строк, каждая — ссылка на список). Правила:
  - СК, у которой есть платежи, ждущие акта больше 60 дней;
  - полисы с активным ДФА, заканчивающиеся в ближайшие 60 дней;
  - потери за последние 30 дней;
  - менеджер, у которого новый бизнес за квартал упал более чем вдвое;
  - число проблем данных, влияющих на деньги.

### B. Деньги — `/analytics/money/`

Вопрос: *«Сколько заработали, сколько придёт, где деньги застряли и
сколько потеряли?»*

1. **По месяцам** (текущий год, переключатель года): заработано по актам
   и план по графику — столбцы + линия; таблица под графиком.
2. **Долг СК по актам:** таблица по страховщикам — КВ, число платежей,
   корзины возраста 0–30 / 31–60 / 61–90 / 90+, самый старый платёж.
   Сортировка по сумме 90+.
3. **Потери:** по месяцам события и по причине (§3.1); разрезы по
   филиалу и СК; итог с начала года и за всё время.
4. **Прогноз на 12 месяцев:** ожидается по графику помесячно (без
   отменённых), с пометкой, что пролонгации не учтены.
5. **Обеспечено на будущие годы:** КВ по годам `due_date` (2027, 2028, …) —
   «хвост» действующих договоров.

### C. Продажи — `/analytics/sales/`

Вопрос: *«Сколько нового бизнеса приводим и откуда?»*

1. Новые полисы и КВ первого года по месяцам (с 2025), отдельно «новый
   полис к старому ДФА».
2. Разрезы (таблица + переключатель): филиал, менеджер лизинга, СК, вид
   страхования — полисы, премия 1-го года, КВ 1-го года, средняя премия.
3. Доля СК в новом бизнесе по кварталам (как меняется выбор страховщика).

### D. Портфель и удержание — `/analytics/portfolio/`

Вопрос: *«Что у нас в силе, что заканчивается и сколько удерживаем?»*

1. **Срез «в силе» на дату** (по умолчанию сегодня): полисы, КВ ожидаемый
   на 12 мес., разбивка по виду / филиалу / СК.
2. **Календарь окончаний на 12 месяцев:** по месяцам — сколько требуют
   продления (ДФА активен) и сколько уходят естественно (ДФА закрыт).
   Клик по месяцу — список полисов.
3. **Удержание** по кварталам: требовали продления → продлены (из них
   ушли к другой СК) → не продлены; процент продления. Приближённый
   расчёт (§3.2), подписан как приближённый.
4. **Отток:** досрочные выкупы и расторжения по кварталам — полисов и КВ.

### E. Страховщики — `/analytics/insurers/`

Вопрос: *«С кем выгодно работать и с кем есть проблемы?»*

Одна таблица, строка = СК:

| Колонка | Источник |
|---|---|
| Полисов в силе | §3.2 |
| Доля в КВ (за период) | заработано + ожидается |
| КВ % по видам (КАСКО / Спецтехника / Имущество) | `kv_rub / amount` |
| Медианный тариф по видам | §3.2 |
| Медиана «оплата → акт», дней | `insurer_date − paid_date` |
| Ждёт акта сейчас (КВ, из них 90+) | §3.1 |
| Потеряно за период | §3.1 |
| Доля в новом бизнесе, изменение к прошлому году | §3.2 |

Клик по СК — та же структура, что у вкладки «Деньги», отфильтрованная по СК.

### F. Каналы — `/analytics/channels/`

Вопрос: *«Какие филиалы и менеджеры лизинга приводят бизнес?»*

- Таблица филиалов и таблица менеджеров (переключатель): новый бизнес
  (полисы, КВ 1-го года) за период и за тот же период прошлого года,
  полисов в силе, КВ ожидаемый на 12 мес., процент продления, потери.
- Отметка у менеджеров/филиалов с падением нового бизнеса.
- Полисы без менеджера — отдельная строка.

### G. Клиенты — `/analytics/clients/`

Вопрос: *«Насколько мы зависим от крупных клиентов и кто требует
внимания?»*

- Концентрация: доля топ-10 / топ-50 в КВ, кривая Парето.
- Таблица клиентов: полисов в силе, КВ за период, ожидается, ближайшее
  окончание полиса, новый / повторный.
- Карточка клиента (по клику): все полисы, платежи, КВ по годам.

### H. ОСАГО — `/analytics/osago/`

Текущая страница (`osago.py`) переносится во вкладку без изменения
логики, с общей панелью фильтров.

### I. Качество данных — `/analytics/data-quality/`

Вопрос: *«Какие ошибки в данных искажают аналитику?»* Каждая строка —
количество + ссылка на список для исправления:

- КВ = 0 при участии брокера;
- ДФА закрыт без даты закрытия;
- полис неактивен без даты расторжения;
- в году полиса нет первого взноса (выпадает из тарифа);
- нет страховой суммы у первого взноса (кроме ОСАГО);
- платёж оплачен раньше даты платежа больше чем на 180 дней (вероятная ошибка ввода);
- нет менеджера лизинга;
- ДФА открыт, полис закончился больше 60 дней назад, а нового полиса по ДФА
  нет — скорее всего, ДФА забыли закрыть (добавлено на этапе 4: на проде
  продление III кв. 2026 — 7 из 56).

### Что удаляется

Страницы и код: старая сводка, филиалы v1, филиалы v2, страховщики,
клиенты, финансы, финансовая история, временные ряды; `chart_providers.py`,
пустые `cache.py`/`filters.py`, DTO из `models.py`, которые больше не
используются; соответствующие листы в `exporters.py`. Пункты меню
«Аналитика» заменяются одной ссылкой.

## 5. Техническое решение

### 5.1. Структура кода

```
apps/analytics/
  money.py            # словарь денег §3.1 (расширяется: потери, причины, обеспечено)
  portfolio.py        # словарь портфеля §3.2 (новый бизнес, продление, отток)
  filters.py          # AnalyticsParams: разбор GET → период, разрезы, ОСАГО
  sections/           # по модулю на вкладку: build_summary(params) → dict
    summary.py  money.py  sales.py  portfolio.py
    insurers.py  channels.py  clients.py  data_quality.py
  drilldown.py        # «список под цифрой»: ключ метрики → queryset + колонки
  export.py           # выгрузка любого drilldown и любой таблицы вкладки в Excel
  views.py            # один базовый view + тонкие view на вкладки
  templates/analytics/
    layout.html       # вкладки + панель фильтров
    tabs/*.html
    includes/         # карточка-цифра, таблица, график, список
```

### 5.2. Правила

- Сервисы возвращают простые словари, не знают про HTTP и шаблоны.
- Только GET; фильтры в URL. Без POST-форм и без сессий.
- Агрегации — одним-двумя запросами с `annotate/values`, без циклов по
  месяцам и без N+1.
- Drilldown: каждая цифра на странице строится из именованного queryset
  (`drilldown.py`), тот же queryset отдаёт список — цифра и список
  совпадают по построению.
- Графики — Chart.js (уже подключён), данные через `json_script`.
- Доступ — `SuperuserRequiredMixin`.

### 5.3. Тесты

- Юнит-тесты словаря (§3) на фикстурах: каждая категория платежа,
  граничные даты, причины потерь, сопоставление продлений.
- Сверка: для любого фильтра «заработано + ждёт акта + ожидается +
  просрочено + потеряно = все платежи».
- Сверка «заработано за месяц» с ежемесячным отчётом по КВ
  (`export_monthly_kv_report`) — одинаковая выборка.
- Smoke-рендер всех вкладок, в т.ч. с ОСАГО в портфеле (как
  `test_osago_smoke`), и всех drilldown-ссылок.
- `tests/test_portfolio_regression.py` продолжает проходить.
